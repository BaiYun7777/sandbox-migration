# 需求单模板（无法自行恢复项登记上库）

> 用途：新沙箱盘点后，把「无法自行恢复、需用户提供或决策」的事项整理成需求单上传资料库，用户逐项回复后关闭。结构沿用 2026-10-17 版（节点 `aZ3r9r7ESElW1819PkdsAp`）。

## 一、文档结构（四表 + 摘要）

```text
标题：《足彩推荐系统 · 恢复需求单（<版本> · <日期>）》
引言（引用块）：背景一句话——沙箱重置了什么、已恢复了什么（带 md5 校验结论）、
              本单登记无法自行恢复、需用户提供或决策的事项，按优先级排列。

一、待用户提供（文件/资料）      表：# | 事项（含现状缺口描述） | 用途 | 优先级
二、待用户决策                  表：# | 事项 | 说明 | 优先级
三、待用户配置 / 使用时提供      表：# | 事项 | 说明
四、已恢复项清单（备查，均已校验）表：资产 | 位置 | 校验
五、恢复摘要                    列表：在线状态 / 数据通道 / 发现的问题 / 下一步
```

## 二、创建方法（library 技能）

1. **骨架法建帖**：`doc/create_doc.py` 先建纯文本骨架（标题 + 五个占位段落）；
2. **表格整表插入**：`doc/submit_doc_edit.py`，动作字段是 **`type`**（不是 `action`），每张表 = 单个 `insert_after`，content 为整个 `<Table>...</Table>` 组件语法——**禁用 Markdown 表格**（会被当纯文本）；
3. 逐表插入 → 删除占位段落 → 提交后用 `get_doc_reviews.py` 回读核对；
4. `node-info` 确认返回 `KS_LAYOUT_NONE` 无碍即成。

## 三、登记原则

- 每项写明**现状缺口**（缺什么、现有什么替代）而非只写名词；
- 优先级分高/中/低；「永久缺失双方皆无」的项注明**低危不用再找**，避免用户重复找；
- 已恢复项必须带 md5 校验结论；问题发现（如 λ 不同源）写入「恢复摘要」并链到处置章节。

## 四、用户批复后的关闭动作

1. 在需求单总结文档（本地 `规范/需求单总结_*.md`）更新各项终态；
2. 批复口令含义：**「批 / 改吧 / 1，改吧」= 部署**；**「同步。明天再跑」= 今天不动**；「不干了」= 该项永久关闭，不再问；
3. 涉及部署的按部署 SOP 六步走，部署后必须问用户是否跑验证（红线）。
